# Как запустить сайт у себя на компьютере

## 1. Поставить Node.js

Нужна версия **20 или новее**. Скачать: https://nodejs.org (кнопка LTS).

Проверить, что встало:

```
node -v
```

Должно напечатать `v20.x.x` или больше.

## 2. Распаковать архив и открыть папку в терминале

**Windows:** правой кнопкой по папке → «Открыть в терминале».
**macOS:** правой кнопкой по папке → «Новый терминал по папке».

## 3. Установить зависимости

```
npm install
```

Это обязательный шаг. Ставится библиотека `sharp` — именно она конвертирует
фотографии в AVIF. Занимает 1–2 минуты, делается один раз.

## 4. Запустить

```
npm run dev
```

В терминале появится:

```
  Сайт:    http://localhost:3000
  Админка: http://localhost:3000/admin
  Логин:   admin / admin
```

Откройте `http://localhost:3000/admin` в браузере, войдите под `admin` / `admin`.

Чтобы остановить сервер — `Ctrl + C` в терминале.

## 5. Где лежат данные

Всё, что вы загрузите локально, складывается в папку **`.local-cms`** внутри
проекта. Это отдельная песочница: боевой сайт `miterova.ru` она не трогает.
Можно грузить что угодно и сколько угодно — просто удалите папку, чтобы
начать с чистого листа.

Свой логин и пароль:

```
ADMIN_USER=alisa ADMIN_PASS=мой-пароль npm run dev
```

## 6. Сколько весит фотография

| | Потолок одного файла |
|---|---|
| Локально (`npm run dev`) | 2 ГБ, то есть практически без ограничений |
| Боевой сайт на Vercel | 4 МБ на запрос — это лимит самой платформы Vercel, поднять его нельзя |

**Ограничения по разрешению нет вообще.** 12000 × 9000, 100+ мегапикселей,
сканы среднего формата — принимается всё, кадрирование не делается.

Если на боевом сайте файл тяжелее 4 МБ, админка сама подберёт сжатие
перед отправкой: сначала опускает качество при **полном разрешении** и только
если этого не хватило — уменьшает пиксели. В процессе она пишет, что сделала,
например «Ужал до 6000×4000, 3,7 МБ».

## 7. Если что-то пошло не так

**`npm install` ругается на sharp** — обновите Node до 20+ и повторите.
Если не помогает: `npm install --include=optional sharp`

**Порт 3000 занят:**

```
PORT=4000 npm run dev
```

**Фотография грузится долго.** Это нормально: AVIF кодируется тем дольше,
чем больше мегапикселей. Кадр 24 МП — примерно полминуты на слабой машине.
Хотите быстрее ценой чуть большего файла:

```
AVIF_EFFORT=0 npm run dev
```

**Хочу файлы поменьше / покрасивее.** Качество задаётся числом 1–100
(по умолчанию 90):

```
AVIF_QUALITY=82 npm run dev
```

## 8. Боевой сайт

Контент боевого сайта живёт не в этом архиве, а в вашем хранилище
Cloudflare R2, в файле `cms/content.json`. Правки в локальной версии на него
никак не влияют, и наоборот.

Переменные окружения для деплоя перечислены в `.env.example`.

---

## Как загружаются фотографии

Лёгкую веб-версию готовит сам браузер: разрешение кадра остаётся полным, а вес
падает в разы. Сервер такой файл просто кладёт в хранилище без перекодирования.

Снимок на 15 МБ превращается в файл порядка 2–4 МБ и спокойно проходит.
**Никаких настроек в Cloudflare для этого не требуется.**

---

## Прямая загрузка в R2 — необязательная возможность

> Этот режим **выключен по умолчанию**. Включать его нужно только если
> хотите хранить исходники целиком без единого пережатия.
> Для обычной работы сайта он не нужен.

Включается переменной `DIRECT_UPLOAD=1` ПЛЮС настройкой CORS на бакете.
Если включить переменную, но не настроить CORS — загрузка сломается.

Тогда файл **не проходит через сервер**:

1. Браузер готовит лёгкую веб-версию (WebP, полное разрешение снимка).
2. Сервер выдаёт временную подписанную ссылку (живёт 15 минут).
3. Браузер кладёт в R2 сразу два файла параллельно:
   - `cms/<uuid>.webp` — то, что видят посетители сайта;
   - `cms/<uuid>.orig` — исходник без единого пережатия.

Функция Vercel только подписывает ссылку, поэтому потолка в 4,5 МБ больше нет
и серверного кодирования AVIF (десятки секунд) тоже больше нет.

### Обязательный разовый шаг: CORS на бакете

Без этого браузер откажется класть файл в хранилище.

1. Cloudflare → **R2** → ваш бакет → **Settings**.
2. Раздел **CORS Policy** → **Edit**.
3. Вставьте содержимое файла `r2-cors.json` из корня проекта и сохраните.

Если домен другой — поменяйте `AllowedOrigins`. Для проверки с превью-деплоев Vercel
добавьте туда же адрес превью.

### Как понять, что CORS не настроен

В админке при загрузке появится сообщение:

> Не удалось связаться с хранилищем. Проверьте настройку CORS у бакета R2.

### Локальный запуск

При `npm run dev` хранилище файловое, поэтому прямая загрузка выключена
автоматически — файлы идут старым путём через sharp. Ничего настраивать не нужно.

### Если оригиналы не нужны

Поставьте переменную `KEEP_ORIGINALS=0` — тогда в бакет ляжет только веб-версия
и загрузка станет ещё быстрее.
